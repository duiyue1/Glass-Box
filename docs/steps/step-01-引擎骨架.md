# Step 1 · 引擎骨架（心脏 + 黑匣子）

> 这一步的目标：**不接任何真实大模型、不用任何 API key**，先把一个 coding agent「跑一个回合」的最小骨架搭起来，并且让它内部发生的每一件事都看得见。

---

## 1. 一句话理解这一步做了什么

我们造了一个「假的 AI 助手」，你对它说一句话，它会走完一个完整的思考回合：
**听你说 → 想 → （需要的话）动手用工具 → 看工具结果 → 再想 → 给你答复。**

关键是：这个过程中的**每一步都被记录并打印出来**了，就像给引擎装了个透明外壳——这就是项目名 "Glass-Box（玻璃盒）" 的由来。

---

## 2. 一个「回合(turn)」到底发生了什么

拿我们跑的例子 `echo Glass-Box 引擎跑通了` 来说，实际发生的流程是：

```
你说: "echo Glass-Box 引擎跑通了"
        │
        ▼
 [thinking]  问模型：这句话要怎么处理？
        │
        ▼
 模型说：请帮我调用 echo 工具，参数 text="Glass-Box 引擎跑通了"
        │
        ▼
 [tool_call]  引擎去执行 echo 工具
        │
        ▼
 [tool_result]  工具返回："Glass-Box 引擎跑通了"
        │
        ▼
 [thinking]  带着工具结果再问一次模型：现在怎么答复？
        │
        ▼
 模型说（纯文本）："工具返回了「...」，任务完成。"
        │
        ▼
 [done]  回合结束，把这句话给你
```

这就是**所有** coding agent（Claude Code / kimi-code / cursor …）最核心的循环，只是它们接的是真模型、工具更多。骨架是一样的。

---

## 3. 这一步的四个零件（对应四个文件）

用一个「餐厅」的比喻来理解：

- **`loop.ts`（后厨主厨 / 心脏）**
  控制整个回合的流程：问模型 → 要不要调工具 → 调完再问 → 直到给出最终答复。
  它内部是一个**状态机**：`idle → thinking → tool_call → tool_result → …… → done → idle`。

- **`wire.ts`（对讲机 + 监控录像 / 黑匣子）**
  厨房里每做一个动作，都对着对讲机喊一声（`emit`），所有戴耳机的人（`subscribe`）都能听到；同时录下来（`history`）。
  **这是玻璃盒的关键**：引擎不藏事，所有内部动作都从这条「事件总线」流出去。后面的 TUI 面板、记忆插件，全都是来这里「听事件」的。

- **`toolRegistry.ts`（工具登记处）**
  引擎自己不认识任何具体工具，工具都得先来这里「报到」。
  好处：以后加工具（读文件、跑命令…）不用改引擎，来登记一下就行。

- **`fakeLlm.ts`（假模型）+ `tools/echo.ts`（示例工具）**
  假模型用几条简单规则冒充真模型的两种行为：**要么让你调工具，要么给你一段文字**。
  echo 工具啥也不干，只把输入原样吐回来——它的作用是**验证「模型→工具→结果→再回模型」这条链路是通的**。

`types.ts` 则是这套系统的「词汇表」，定义了消息、工具调用、事件长什么样。

---

## 4. 为什么这么设计（三个关键决定）

1. **先用假模型（FakeLlm）**
   真模型要 key、要花钱、还慢。骨架阶段用假模型，`node src/index.ts` 秒级就能跑通，专注把「流程」调对。Step6 才换真模型——而且**只换 `fakeLlm.ts` 一个文件**，引擎其它部分一行都不用动（因为大家都只依赖 `Llm` 这个接口）。

2. **一切都走 wire 事件总线**
   我们没有让引擎直接 `console.log`，而是让它 `emit` 事件，再由外部订阅者决定怎么展示。
   这样「引擎逻辑」和「怎么展示」彻底分开——Step3 换成漂亮的 TUI 面板时，引擎代码完全不动。

3. **工具通过登记处解耦**
   引擎只认 `ToolRegistry`，不认具体工具。这是 Step2「插件化」的地基。

## 5. 怎么自己跑一下

要求：Node ≥ 22.6（本机是 v23，可直接跑 `.ts`，无需编译）。

```bash
# 方式一：调用工具的回合（会看到完整的 tool_call 流程）
node src/index.ts "echo 你好世界"

# 方式二：纯聊天的回合（模型直接给文本，不调工具）
node src/index.ts "今天天气怎么样"

# 方式三：用默认输入
npm run demo
```

你会看到一条带时间戳的时间线，把回合内部的状态切换、模型请求、工具调用逐条打出来。**这条时间线就是玻璃盒 Step1 的形态。**

## 7. 踩的一个坑（顺便学个知识点）

一开始 `Loop` 的构造函数用了 TypeScript 的「参数属性」简写（`constructor(private wire: Wire)`）。
Node 直接跑 `.ts` 用的是「**只擦除类型**」模式，它不支持这种会**生成额外代码**的语法。
所以改成了老实写法：先声明字段，再在构造函数里赋值。
**结论**：直接用 Node 跑 TS 时，避开「参数属性、enum、namespace」这类「不只是类型、还会生成代码」的语法。
