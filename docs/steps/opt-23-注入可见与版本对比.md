# 优化 23 · 把检索过程摆到面板上 + 版本 diff + 时效三档

三件事都属于「数据早就有了，只是看不见」。资料库是整条链路里唯一一个
**事件里什么都有、面板上只看得到标题** 的地方——这跟「玻璃盒」这个卖点直接冲突。

## 1. 注入正文与检索口径（第 2 批）

`kb.injected` 事件里躺着五个没人看得见的字段。opt-20 就写进去了，一直只在 jsonl 里。

- `content`：**真正拼进提示词的那几段正文**，一字不差。审计口——事后能复核模型到底看到了什么。
- `query`：真正拿去检索的字符串。**不是用户原话**：去过停用词、可能拼了上一轮的关键词。
- `usedPrev`：这一轮是否借了上一轮的关键词（多轮指代兜底有没有生效）。
- `belowThreshold` / `cappedByDoc` / `dropped`：分别被「相对阈值」「一篇最多 3 块」「token 预算」挡下了几段。

面板上现在长这样（真实 GLM-5.2 一回合，问「分布式锁的租约是多久，续租周期呢」）：

```
资料库  2 篇 · 11 块 · 注入 5 段（712/800 tok，命中 8 丢 1）
◆ 调度服务 SDD > 1. 概述        BM25 1.24 · 118 tok · 上文
◆ 调度服务 SDD > 3. 分布式锁     BM25 4.07 · 205 tok
...
查询串: 分布式锁 租约是多久，续租周期
丢弃: 2 段低于阈值 · 1 段超预算
[查看注入正文]  ← 点开是完整的 content
```

为什么这几个字段值得占面板位置：**「为什么这次没检索到」以前只能翻 jsonl。**
今天那个「跳过率 → 跳 率」的停用词 bug，就是靠打印 `query` 才发现的——
在面板上常驻显示之后，这类问题不用等我去查日志。

一段没命中时也会显示（`这一轮没有注入任何资料` + 查询串 + 丢弃统计），
因为「没注入」恰恰是最需要解释的情况。`GB_KB_LOG_TEXT=0` 时事件里没有 `content`，
按钮就不出现，不给一个点了没反应的死按钮。

每回合开头会清掉上一轮的正文和口径——否则你看到的是上一轮的证据，比没有更糟。

## 2. 版本 diff（第 3 批）

已有 `versions()` / `rawVersion()` / `rollback()`，缺的是「回滚前先看清改了什么」。
以前只能把两版全文各读一遍自己比。

`src/kb/diff.ts`，零依赖，两个纯函数：

- `lineDiff(old, new)`：标准 LCS 动态规划 + 回溯出编辑脚本。
  **同一处修改表现为「先 del 再 add」，不合并成 change**——合并之后行号对不上，面板上更难看。
  行号按各自版本编号（新增行没有 `oldNo`，删除行没有 `newNo`）。
  规模上限 100 万格（≈1000×1000 行），超了退化成「整体替换」——宁可显示得粗糙，也不让面板卡死。
- `collapseSame(lines, context = 2)`：只留改动处 + 上下 2 行，中间折成一条 `省略 n 行未改动`。
  长文档全文对比没人看，看的是改了哪几处。

末尾换行不算一行差异，`\r\n` 归一——不然每次 diff 都会多出一堆假差异。

接口 `GET /kb/diff?id=&from=&to=`（`to` 默认当前版本），面板上每个历史版本多一个「对比当前」按钮，
加行绿、减行红、省略行灰。实测：

```
v1 → v2：+2 行 / -1 行
  ⋯ 省略 2 行未改动
  ## 1. 交接
- 周三 14:00 交接。
+ 周三 14:40 交接。
  联系人：张三。
  ⋯ 省略 1 行未改动
+ 再找架构师。
```

## 3. 时效三档（第 3 批）

原来 90 天一刀切标「久未更新」。问题是**不分级**：60 天的和 300 天的长得一样，
你没法判断该先更新哪篇。改成 doarchon `wiki-freshness.ts` 的分法：

- `< 30 天`：**不打标**。满屏绿标签等于没标。
- `30 ~ 60 天`：黄色「待复核」——扫一眼是否还准确。
- `≥ 60 天`：红色「已过期」——内容很可能和现状不符，**但它照样会被当权威注入**，这是提示语的重点。

你现在这两篇资料都是三天内导入的，所以面板上**一个标签都不会出现**——这是对的，不是没生效。

## 已知缺口

- **注入正文是整段（所有片段拼在一起），不是每条一个展开**。因为 `kb.injected.items` 里
  只有标题/分数/token，正文只在 `content` 这一个字符串里。要做到「点某一段看它的正文」，
  得给每个 item 加 `text`，等于把同样的内容存两份——先不做。
- **diff 只有行级，没有行内高亮**。改一个数字会显示成整行删+整行加。行内 diff 要再来一层
  字符级 LCS，等真的觉得不够用再说。
- **Web 端点仍然没有鉴权 / CSRF 防护**。这轮又多了一个读端点（`/kb/diff` 能读任意历史版本原文），
  仍然只靠绑 127.0.0.1。这是这个项目里最该先补的洞。
