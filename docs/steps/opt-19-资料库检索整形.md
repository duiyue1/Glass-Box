# 优化 19 · 资料库检索整形（第一批）

参考 AI-Ku 的 `doc_store`（`qdrant_store.search` + `service.rag_query`）里已经踩过的经验，
先做**不需要任何外部能力**的那一批：结果整形 + 查询构造。

对齐的地方：AI-Ku 的检索是「Dense + BM25 混合 → 权限过滤 → **按 doc_id 去重、每篇留 top-3**
→ 拼上下文（含来源标注）」。我们的分块/ID 设计本来就和它一致
（`MD5(doc_id::chunk_index::version)`、`heading_path`、`chunk_type`、`doc_status`），
差的是**后半段的整形**。

## 改了四件事

### 1. 每篇文档最多贡献 N 块（`perDoc`，默认 3）

之前是全局排序取前 4 条。一篇长文档能把预算吃光，另一篇更贴题的短文一段都进不来。
被这条挡掉的数量单独记成 `cappedByDoc`——它和「预算不够」是两回事，混在一起就看不出该调哪个参数。

### 2. 相对分数阈值（`minScoreRatio`，默认 0.3）

BM25 只要沾上一个词 `score` 就 > 0。原来问「今天几号」也可能塞几段无关资料进去，
白占预算还干扰模型。现在低于最高分 30% 的直接丢，记成 `belowThreshold`。

### 3. 命中块的上文补全（`withNeighbor`，默认开）

命中章节中段时，把**同章节的上一块**一起带上，`formatHits` 里标注「（上文）」。
两条约束：
- 它**不占 `maxItems`**（它不是一条命中，是被切断的上文）
- 但**占 token 预算**，装不下就不带——宁可少给，也不超预算

### 4. 查询构造（`src/kb/query.ts`）

之前把用户原话整句丢给 BM25。两个问题，一个个治：

- **口语词稀释关键词**：`normalizeQuery()` 去掉「帮我/看看/是什么/怎么」这类停用词；
  整句都是停用词时退回原文（宁可噪音，也别得到空查询）
- **指代失效**：「它重试几次？」句子里没有主语，检索必然为空。
  `buildQuery(userText, prevKeywords)` 在两种情况下借上一轮的关键词：
  实词过少，**或者句子里出现指代词**（它/这个/上面/刚才…）

一个踩到的坑：`keywordsOf()` 必须用**不兜底**的 `stripStop()`。
否则「它呢」整句被判成停用词后退回原文，`["它呢"]` 就成了下一轮的关键词，话题链直接被带偏。

用了哪个查询串、有没有借上一轮，都记进 `kb.injected` 事件（`query` / `usedPrev`），
轨迹页能直接对账——不然"为什么这次没检索到"根本查不动。

预算同时从 4 条 / 400 tok 提到 **6 条 / 800 tok**（`GB_KB_ITEMS` / `GB_KB_TOKENS` /
`GB_KB_PER_DOC` / `GB_KB_MIN_RATIO` / `GB_KB_NEIGHBOR` 可覆盖）。

## 验证

**单测**：157 → **166 全绿**，新增 9 条覆盖：停用词过滤不清空查询、关键词抽取去重有上限、
指代句才借上一轮、连续指代时话题链不断、perDoc 上限 + `cappedByDoc`、阈值挡掉弱命中、
上文补全不占条数且顺序正确、token 不够时不带上文、`formatHits` 标注「（上文）」。

`tsc --noEmit` 无错。

**真实语料对比**（临时工作区导入两篇文档：长 SDD 4 节 + 短运维手册，共 5 块）：

```
问「抢锁失败怎么处理」
旧参数(4条/400tok): 命中2 tok325 | SDD::2 ; 运维手册::0
新参数(6条/800tok): 命中2 +上文1 tok640 低分挡1 | [上文]SDD::1 ; SDD::2 ; 运维手册::0
问「今天星期几」    : 两者都 0 命中（这份语料里没有能沾上的词）
```

**真实模型实跑**（gpt-5.5，你的 `.env` 原样）：

```
你> 抢锁失败之后应该怎么处理？
   kb.injected: query="抢锁失败之后应该 处理？" usedPrev=false 命中3 tok640/800 低分挡1
   片段: [上文]SDD>4.3 分布式锁(315tok) ; SDD>4.3 分布式锁(316tok) ; 运维手册>抢锁失败排查(9tok)
AI> 先等 3 秒再重试，重试 3 次仍失败则告警并跳过本次调度…（并引用了两处来源标题）

你> 它重试几次？
   kb.injected: query="重试几次？ 抢锁失败之后应该 处理" usedPrev=true 命中3 tok640/800
AI> 重试 3 次。来源：《调度服务 SDD > 4.3 分布式锁》
```

第二问是纯指代句。**改动之前这句检索必然是 0 命中**（`它/几次` 打不中任何块），
现在靠上一轮关键词把话题接上了，模型答出了具体数字并给了来源。

## 没做的（留给后面几批）

- **混合检索**：BM25 打不中同义表述（"抢锁失败" vs "获取锁超时"）。要上向量得先探测网关有没有
  `/embeddings`，还没探
- **`kb_search` 工具**：现在仍然只有被动注入，模型不能主动换关键词重查
- **治理**：版本历史（同名导入仍然覆盖 `raw/`）、重复检测、时效标记、重新索引、敏感信息扫描
- `kb.injected` 只记了标题/分数/token，**没记实际注入的正文**——详情里点开还是看不到原文
