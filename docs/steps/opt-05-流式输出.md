# 优化 05 · 流式输出（SSE + 逐字显示）

> 之前模型回复是"憋很久，然后一次性蹦出来"。这一步接上**流式输出**：边生成边打印，交互体感终于像真正的 coding agent。难点不在拉流，而在**别把内部指令漏到屏幕上**。

---

## 1. 一句话理解这一步

真实模型接口支持 SSE（Server-Sent Events）流式返回，一小段一小段地吐 token。我们把这些增量通过事件总线广播成 `llm.delta`，chat 界面订阅它就能逐字显示。

假模型也做了模拟流式，所以**零凭证也能看到流式效果**。

---

## 2. 核心难点：ACTION 指令不能漏出去

模型每一轮回复有两种可能：
- 要调工具 → 输出 `ACTION: grep StreamGate`（这是**给引擎看的内部指令**）
- 给最终答复 → 输出正常文本（这是**给你看的**）

问题是：流式场景下，token 一个个来，**开头几个字符还看不出是哪种**。如果无脑打印，`ACTION: grep ...` 就会漏到屏幕上，很丑也很困惑。

解决方案是一个"闸门" **`StreamGate`**：

```
攒一小段 → 到换行 / 攒够 64 字符 / 流结束时判定
   ├─ 判定为 ACTION（内部指令） → 整轮一个字都不显示
   └─ 判定为普通文本           → 把攒的一次吐出，之后 token 直接放行
```

同时容忍 ```代码块``` 包裹的 ACTION（复用了优化 04 的思路）。

实测（真实模型，一次含工具调用的对话）：
```
第1轮流式输出: ""                        ← ACTION 轮，完全静默
第2轮流式输出: "代码库里没有找到 ..."      ← 文本轮，正常流式
是否有 ACTION 泄漏: false
```

---

## 3. 数据怎么流的

```
RealLlm 拉 SSE 流
   ↓ 每个 delta
StreamGate 判定（该显示吗？）
   ↓ 该显示的部分
onToken 回调
   ↓
Loop 广播 wire 事件 llm.delta
   ↓
chat 订阅 → 逐字写到终端
```

关键设计：**引擎不关心流式细节**。`Llm` 接口只是多了一个可选参数：

```ts
interface Llm {
  complete(messages: Msg[], onToken?: TokenSink): Promise<LlmResponse>;
}
```

`Loop` 传进去一个把增量转成 `llm.delta` 事件的回调。于是流式能力也变成"事件总线上的又一种事件"——TUI、日志、chat 谁想用谁订阅，不想用就忽略。老的测试桩（只实现 `complete(messages)`）**一行都不用改**，因为参数是可选的。

---

## 4. 失败回退

流式请求**不做重试**（重试会导致已输出的内容重复）。取而代之：
- 若流式失败且**一个 token 都还没吐出** → 安全地回退到非流式请求（那条路径带重试，见优化 04）。
- 若已经吐出过内容才失败 → 直接报错，不回退，避免重复输出。

---

## 5. 配置

- `GB_STREAM=0` — 关闭流式（回到一次性返回）
- `GB_FAKE_STREAM_DELAY` — 假模型模拟流式的每块延迟毫秒（默认 0，设成 30 可以看清逐字效果）

```bash
# 真实模型流式对话
npm run chat

# 零凭证也能看流式（放慢便于观察）
GB_LLM=fake GB_FAKE_STREAM_DELAY=30 npm run chat

# 关掉流式对比一下
GB_STREAM=0 npm run chat
```

## 7. 回归测试与端到端验证

```
npm test  →  32 passed / 0 failed
```

端到端（真实 gpt-5.5）：
- 纯文本问答：`llm.delta` 触发 **108 次**，累计 187 字符，**与最终文本长度完全一致**（说明流式内容无缺失）。
- 含工具调用：ACTION 轮流式输出为空、文本轮正常流式、**无 ACTION 泄漏**。
- 假模型：同样触发 28 次 delta。

**一个如实的观察**：某次真实模型运行中，grep 工具明确返回了 `StreamGate` 的匹配结果，但模型却答"代码库里没有找到"。复查确认——工具调用参数正确、工具结果正确（我单独验证过 `grep StreamGate` 能正确命中 3 个文件），这是**模型本身偶发的误读**，不是链路 bug。这也正是玻璃盒的价值：因为每一步都可观测，才能快速判定"是模型错了，还是我的代码错了"。
