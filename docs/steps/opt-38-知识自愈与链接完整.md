# opt-38 · 知识自愈：过期条目不再当权威，坏链孤岛能量出来

## 起因

一个提问暴露的：**原文重导入后，wiki 条目会发生什么？**

查完代码的答案是——资料库那一层干净（同标题重导入 = 版本 +1、旧原文进 `raw/history/`、旧分块整体替换，新旧内容不共存），但 wiki 这一层有三个洞：

1. `sourceHash` 能判出条目过期（`freshness` 维度早就有），可 `pickCatalog` 只过滤"未通过校验"和"缺摘要"，**过期条目照旧当权威注入**。体检报告写了"这页过期"，处方没人执行。
2. 没有"重建全部过期条目"的入口，只有逐页点。
3. `[[ref]]` 指向不存在的条目没人校验；`buildDocWiki` 只 `write` 不 `remove`，改版后旧 ref 的 `.md` 留在盘上照样被 `list()` 读出来。

顺带一个记账不一致：`related` 在手改路径是 `extractLinks(body)`（web.ts），在生成路径只信模型 frontmatter 里声明的（`...parsed`）。模型正文写了 `[[concept/x]]`、frontmatter 忘了列，图上就少一条边——跟当初 `sources` 那个坑一模一样。

## 抄了谁

- **Graphiti**（27.7k，Apache-2.0，arXiv:2501.13956）：矛盾的边不删，设 `invalid_at`。这直接决定了这次的策略——**过期条目标注、降权，但不排除、不删除**。
- **mem0**（63.7k）的反面教材：AUDN 里 DELETE 分支的已知缺陷（issue #4536：「我爱中餐」→「我讨厌中餐」触发 DELETE 却不 ADD，冲突消失了，信息也丢了）。删除式冲突解决有代价。
- **Dendron Doctor 的 `findBrokenLinks`** 和 Obsidian 找孤儿/断链的插件：坏链和孤岛在成熟 wiki 里是例行体检项，不是一次性排查。

## 四处改动

**1. 过期条目降权 + 标记（`wikiStore.ts`）。** `CatalogOpts` 加 `isStale?`，由 app.ts 传（`isStalePage`，跟质检共用同一份判定）。排序改成"新鲜的在前、过期的在后"，所以预算不够时**天然先挤掉过期的**；挤不掉就在目录行里标 `（已过期，以原文为准）`。source 页压成一行没地方逐条标，用 `ref*` + 一句 `（*=已过期）`。

那句说明**只有 8 tok，是量过之后压出来的**：第一版写"（带\*的依据原文已改动，以原文为准）"要 20 tok，而 source 那一行的子预算只有 `240×0.25=60` tok（前缀本身 29 tok），单测直接抓到它挤掉了一个 ref。另外 `estimateText('*')` 单独估是 3 tok（最小档位罚的），所以 `*` 要跟 ref 拼在一起估。

**为什么不排除**：排除是更简单的实现，但模型会连"有这么一页"都不知道，连去核对原文的机会都没有。标注版至少留着那个指针。

**2. `--stale` 只重建过期条目（`app.ts` / `kbWiki.ts` / `web.ts` / 面板按钮）。** 按"过期条目属于哪篇资料"分组（`staleRebuildJobs`，纯函数、可单测），每篇只重建那几个 ref。两处不肯静默的地方：来源资料被归档/删掉的条目挑成 `orphans` 报出来（它仍然在被注入）；点名要重建、却既没生成也没报错的，说明**新的页面结构里已经没有这一页**，会一直过期下去，也报出来——按"标注不删"的规矩不自动删。

已知代价：结构规划照样要调一次模型（页面清单是模型给的，不重新规划就不知道 ref 还在不在），所以省的是编译那几次，不是全部。

**3. 质检加第六维「链接完整」（`wikiAudit.ts`）。** 三类机械可判的问题：坏链（`[[..]]` 指向不存在的条目）、孤岛（没人引用它、它也不引用别人；source 页不算，它是入口；只有一条条目时不判——无处可连不是缺陷）、无主（它引用的原文块**全都**不在启用中的资料里了）。

⚠️ **口径变更**：权重重排（可检索 0.15→0.1、精炼去重 0.2→0.15、链接完整 0.1）。`quality.jsonl` 里 opt-38 之前的**综合分与之后不可直接比**，单维度分仍然可比。这一条写进了 `wikiAudit.ts` 的头注释。

**4. `related` 口径统一（`wikiBuild.ts`）。** frontmatter 声明的 ∪ 正文实抽的，去掉自引用。**指向还不存在的条目不过滤**——条目是一页一页生成的，被引的那页可能还没编译到，按存在性过滤会让结果依赖生成顺序。坏链交给质检报。

## 实测

`npm test` 358 条全绿。真实模型（gpt-5.5）在 `/tmp` 的干净工作区跑完整自愈闭环：

1. 导入《调度服务 SDD》（TTL 30 秒），`buildWiki` → 3 条条目全部通过溯源校验，过期 0。
2. 把 TTL 改成 45 秒重导入（v2）→ **过期 3 条**，面板树上三个 stale 全亮。
3. 跑一个真实回合问"锁的 TTL 是多少秒"，日志：
   `[知识目录] 注入 3 条(162/240tok，3 条已过期): source/调度服务-SDD(过期) | concept/分布式锁(过期) | concept/重试策略(过期)`
   （改动前这一行只有 `注入 3 条(162/240tok)`，过期完全不可见。）
4. 质检：综合分 **70.4**，时效 0、链接完整 33.3。
5. `kb:wiki --stale` → 3 条重建，正文变成"TTL 是 45 秒，续租周期 15 秒"。
6. 复检：过期 **0**，综合分 **97.3**，时效 100、链接 100。

## 两个诚实的观察

**第一次生成时模型一个 `[[..]]` 都没写**，两个 concept 页都被判成孤岛（链接维度 33.3）；重建那次 source 页写了两个链接，两个 concept 页因此有了反向链接，链接维度跳到 100。也就是说**这一维量到的是模型行为的抖动，不是这次改动带来的提升**——它的价值是让"图到底建起来没有"第一次变成一个数字，而不是让分数变好看。opt-24 记的那个老现象（同一份提示词几轮之间格式失败数在 0~4 跳）在链接这件事上同样成立。

**过期条目留在目录里没有害处，前提是模型会去查原文。** 第 3 步里模型看到三条过期指针后调了 `kb_answer`，答的是 45 秒（新值）——它没拿过期条目当答案。但这是一次观察，不是保证；n=1。

## 没做的

- 图距离扩展一跳（命中一页顺带给邻居的 ref）、Obsidian 那种 Unlinked Mentions（正文提到某页标题但没建链，主动提示补链）：等链接维度在真实资料上跑几轮，看坏链/孤岛的真实数量再判值不值。
- 跨文档的内容矛盾（两篇不同标题的资料说了相反的话）：`duplicatesOf` 只在导入后给一个相似度警告，不拦不合。LightRAG 也一样（issue #2528 明说不做语义矛盾处理），这是这一档实现的通病。真要做，按 Graphiti 的路子给条目加 `supersededBy` 标注，而不是 mem0 那种删除。
- 孤儿 `.md` 的自动清理：现在只报不删。
