# 优化 16 · 分叉后的记忆可见性（B+ 规则）

## 要解决的矛盾

opt-15 做完分叉后，实跑暴露一个问题：**分叉只回退了对话历史，记忆没回退**。

```
回合 1  记住：数据库用 MySQL 8.0
回合 2  记住：我们决定把数据库换成 PostgreSQL 16
        ↑ 你觉得这个决定不对，想回到回合 1 重新讨论 → 分叉
分叉后  「我们的数据库用什么版本？」
        → 记忆把两条都注入回来，模型说"你们原来 MySQL，后来换成 PostgreSQL"
```

想回到"还没决定换"的那一刻重新想，它却还记得你换了 —— **分叉这个功能等于白做**。

但粗暴地"分叉时把记忆全关掉"也不对：记忆里除了事实，还有你的说话偏好和禁令
（"不要用中文回答数据库问题"）。那些跟时间无关，回退到哪一步都该守。

## B+ 规则

按原子的 `kind` 分两类处理：

- `fact` / `event`（当时发生的事、你说过的话）→ **按时间切**：分叉丢掉的那段时间里产生的，不再注入
- `preference` / `constraint`（你是个什么样的人、有什么规矩）→ **永久生效**，分叉不影响

```ts
// memory/store.ts
export function isHiddenByFork(atom: Atom, hidden: readonly HiddenRange[]): boolean {
  if (atom.kind === 'preference' || atom.kind === 'constraint') return false;
  return hidden.some((r) => atom.ts > r.from && atom.ts < r.to);
}
```

## 为什么用时间戳而不是 seq

第一反应是给原子记下产生它的 `seq`。但**分叉后新会话的 seq 从自己的编号空间重新长**，
两条线的 seq 会撞，比不了大小。而 Atom 本来就有 `ts` 字段，用时间戳天然全局有序。

## 屏蔽窗口是「一段区间」，不是「一个上限」

不能简单地"只注入 ts ≤ 分叉点"的原子——那样分叉之后**新产生**的原子也会被挡掉。
正确的形状是一个左开右开区间：

```
from = 分叉点那一刻的 ts        （turn.end 事件的 ts，由 rebuildInfo 带出来）
to   = 执行分叉的那一刻         （session.started 事件自身的 ts）
```

`(from, to)` 之间产生的 fact/event 被丢弃；早于 from 的照旧可见；晚于 to 的（分叉后新说的话）
不受影响。反复从不同点分叉就累加多个窗口。

## 窗口不用另外存——从日志就能算回来

每个分叉出来的会话，第一条 `session.started` 里已经记着
`forkedFrom: { sessionId, seq, ts }` 和事件自身的 `ts`，两者正好就是窗口的两端。
所以 `--resume` 一个分叉会话时能重新推导出同样的屏蔽效果，而且**顺着 `forkedFrom` 往上走
还能把多级分叉的窗口全部还原**（`forkHiddenRanges`，最多回溯 8 层）。

这是事件溯源的又一次红利：状态不用持久化，因为历史已经持久化了。

## 顺手修的一个真 bug：约束存进去意思反了

`distill()` 里约束是这么抽的：

```ts
if ((m = text.match(/(?:不要|别|禁止|不准)\s*(.+)/))) atoms.push(makeAtom('constraint', m[1].trim()));
```

`m[1]` 是**否定词后面那半句**。"不要用中文回答" 存进去变成 **"用中文回答"**——
意思正好反了，模型照着做就错了。改成取 `m[0]`（整段，含否定词）。

有测试盯着这条：`assert.equal(seen[0], '不要用中文回答数据库问题')`。

## 观测

`memory.injected` 事件多了 `hiddenByFork` 字段：**命中了但因分叉被屏蔽的条数**。
CLI 日志和 Web 面板都会显示，命中的全被屏蔽时也会单独提示一行。
玻璃盒的原则不变：不是"它变聪明了"，而是"我看得见它为什么这么答"。

## 验证

**单测**：套件 126 → 131 全绿。

- fact/event 在窗口内被屏蔽、constraint 在同一窗口内照旧可见、分叉后新产生的可见、`hiddenByFork` 计数
- 没有窗口时行为和以前完全一致（向后兼容）
- `forkHiddenRanges` 能从日志推导单级和**多级**分叉的窗口（c ← b ← a 两段都还原）
- `rebuildInfo` 带出分叉点的 `atTs`
- 约束保留否定词

**真实模型 A/B 对照**（gpt-5.5，你的 `.env` 原样配置，无任何 `GB_*` 开关）：

三个回合先后说：`记住：数据库用 MySQL 8.0` → `记住：我们决定把数据库换成 PostgreSQL 16`
→ `不要用中文回答数据库问题，数据库相关一律用英文`。然后问同一句「我们的数据库用什么版本？」

```
【对照组】不分叉，原会话里问：
  There's a conflict in the notes: - MySQL 8.0 - PostgreSQL 16
  Please confirm which one should be the current database.
  → MySQL:True  PostgreSQL:True  英文

【实验组】分叉回第 1 个回合（那时还没决定换），问同一句：
  MySQL 8.0.
  → MySQL:True  PostgreSQL:False  英文

  记忆注入: [('fact','数据库用 MySQL 8.0'), ('constraint','不要用中文回答数据库问题，数据库相关一律用英文')]
  hiddenByFork = 2
```

三件事一次证完：

1. 分叉点之后的**事实**被挡住了（PostgreSQL 没出现，`hiddenByFork=2`）
2. 分叉点之后才立的**规矩**仍然生效（两组都用英文回答——那条约束是在回合 3 说的，
   比分叉点晚，但因为是 constraint 所以没被屏蔽）
3. 分叉点之前的事实照常可用（MySQL 8.0 答得出来）

对照组那句"notes 里有冲突，请确认用哪个"也顺带说明了**不做 B+ 会是什么体验**。

## 中途踩的一个坑（值得记）

第一次跑真实验证时，提示词写成了「记住：数据库用 MySQL 8.0。**只回复"记住了"。**」，
结果整句都被存进了原子，连"只回复 OK"也进去了，分叉后模型就真的只回了个 "OK"。

机制是对的（事件流里 `hiddenByFork=1`、注入内容都正确），但答案没法看。
这暴露了正则蒸馏的固有粗糙：**它把整个句子尾巴都当成事实内容**。
第二次把提示词里的指令尾巴去掉才得到干净的对照结果。

这条限制没修——修它需要让模型来做蒸馏（一次额外的模型调用），属于另一个决定。

## 已知限制（说清楚）

- **记忆检索是关键词匹配**，所以"不要用中文回答数据库问题"这条约束只有在你问的问题里
  也出现"数据库"时才会被召回。全局性的规矩（"回答简短点"）在词面不重叠时召回不到。
  这是 L1 记忆用词项重叠检索的老问题，不是 B+ 引入的
- 屏蔽窗口最多回溯 8 层分叉链，超过就不再往上找
