# 快速上手

Glass-Box 是一个跑在终端里的迷你 coding agent。你用自然语言给它派活，它自己决定读哪个文件、跑哪条命令；
特别的地方是**它每一步在想什么、调了什么工具、为什么要向你要授权，全都摆在屏幕上**。

不需要 API key 就能先跑通全流程（内置一个"假模型"顶着）。下面按顺序走一遍，大约十分钟。

---

## 第 0 步：只要装一个东西 —— Node.js

**版本必须 ≥ 22.18**。这是能不带任何编译步骤直接运行 `.ts` 文件的最低版本，整个项目就靠它省掉了构建。

```bash
node -v        # 看看够不够，要 v22.18.0 以上
```

不够或者没装：

```bash
# macOS / Linux，推荐用 nvm 装，不污染系统
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
nvm install 22

# macOS 用 Homebrew 也行
brew install node
```

Windows 到 [nodejs.org](https://nodejs.org) 下安装包即可（项目在 Windows 上正常跑，CI 有 Windows 矩阵）。

**除此之外什么都不用装。** 这个项目运行时零第三方依赖，克隆下来直接就能跑，`npm install` 都可以先跳过。

---

## 第 1 步：把项目下载下来

```bash
git clone https://github.com/<你的用户名>/Glass-Box.git
cd Glass-Box
```

没装 git 的话，在 GitHub 页面点 `Code` → `Download ZIP`，解压后 `cd` 进去也一样。

想跑类型检查（`npm run typecheck`）再执行 `npm install` —— 它只会装 `typescript` 和 `@types/node`
两个开发期依赖，不进运行时。

---

## 第 2 步：跑通第一条命令（不需要 key）

```bash
node src/index.ts "echo 你好世界"
```

屏幕上会滚一串带时间戳的日志，这就是"玻璃盒"：

```
[Glass-Box] 使用模型: FakeLlm                          ← 当前用的是假模型
[插件] 加载 fs: read_file, write_file, edit_file        ← 它手上有哪些工具
[插件] 加载 shell: run_command, read_output, kill_command
[技能] 可用: code-review, git-commit, ...               ← skills/ 里的技能
>> 回合开始: "echo 你好世界"
   状态: idle -> thinking                              ← 状态机在走
   <- 模型: 工具调用: echo                              ← 模型决定调工具
   [工具] echo({"text":"你好世界"}) → 结果: 你好世界
   状态: thinking -> done
最终回复: 工具返回了「你好世界」，任务完成。
会话日志: .../.glassbox/sessions/s_xxxx.jsonl           ← 这一跑的全部事件都存下来了
```

看到 `最终回复` 就算跑通了。`使用模型: FakeLlm` 说明当前是假模型 —— 它不联网、不花钱，
按固定规则把你的话翻译成工具调用，专门用来验证"模型 → 引擎 → 工具 → 结果 → 再回模型"这条链路是通的。

> 看到 `ExperimentalWarning: Type Stripping` 是正常的，那是 Node 在提示"我正在直接跑 .ts"，不是报错。

---

## 第 3 步：挑一个入口玩起来

四个入口跑的是同一个引擎，只是把内部状态"显示"给你的方式不同。**第一次建议直接从 Web UI 开始**，最直观。

```bash
npm run web     # 浏览器里的玻璃盒 → 打开 http://127.0.0.1:7777
```

左边是对话和它做过的动作，右边是实时面板：状态机走到哪、上下文用了多少、命中了哪个技能、
调了什么工具、要你授权的弹窗（改文件时会彩色显示 diff）。端口被占用就 `GB_PORT=8888 npm run web`。

> 它只监听 `127.0.0.1`，不对外网开放 —— 这个 agent 能执行命令、能读写文件，绝不能暴露出去。

另外三个：

```bash
npm run chat    # 终端里多轮对话，最常用。/panel 看面板 · /new 开新会话 · /help · /exit
                # 一个回合跑飞了按 Esc 掐掉它，做过的步骤留在历史里，接着聊就行
npm run tui     # 分屏界面：左对话流 / 右面板，适合演示
npm run demo    # 一条命令跑完就退出，适合看完整日志或塞进脚本
```

## 第 4 步：它要动手之前会问你

读文件、搜代码这类没有副作用的操作它自己就做了。**写文件、执行命令这类会留下痕迹的，会停下来问你**：

```
[需确认] 执行命令: npm test
是否允许？[y=允许 / a=以后同类不再问 / N=拒绝]
```

三个键：

- `y` 允许这一次
- `a` 本次会话内**同类**操作不再问（只有普通风险的操作给这个选项）
- 直接回车 = 拒绝（选项里大写的 `N` 就是默认值）

风险分四级，从低到高是 `safe`（不问）→ `confirm`（问一次）→ `dangerous`（打上 `[危险]` 标记并说明原因，
而且**永远不能记成"以后不再问"**）→ `deny`（**直接拒绝，根本不问你**，比如写 `.git` 目录、读 `.env` 这类凭证文件）。
最后一级拦在引擎里，你手动点"允许"也放不过去。

## 第 5 步（可选）：换成真实模型

假模型只能照着固定规则翻译指令，真正干活得接一个 OpenAI 兼容的模型。在项目根目录建一个 `.env`，
**前三行是必需的**：

```
MIDSCENE_MODEL_BASE_URL=https://<你的接口地址>/v1
MIDSCENE_MODEL_NAME=<模型名>
MIDSCENE_MODEL_API_KEY=<你的 key>
```

存好再跑任意入口，启动时那行会变成 `使用模型: RealLlm(<模型名>)`，就成功了。

```bash
npm run chat                                  # 接着正常聊，它会自己去读写文件、跑测试
GB_LLM=fake npm run chat                      # 想临时退回假模型（离线、演示、省钱）
```

`.env` 已经写进 `.gitignore`，不会被提交。分享项目时别把它一起发出去。

## 在你自己的项目上用它

不用把代码拷进来，也不用 `cd` 过去，加一个 `--workspace` 就行（简写 `-C`，跟 `git -C` 一个意思）：

```bash
npm run chat -- --workspace ~/code/my-project
```

这个目录就是它的**活动范围**：能读能改的是这里面的文件，越界要单独向你要授权，会话日志和记忆也存在
这个目录的 `.glassbox/` 下。目录必须已经存在，它不会替你新建。

**一个容易踩的坑**：`.env` 只会从你**当前所在目录**读取。在别的地方跑的时候，要么先 `cd` 回 Glass-Box 目录，
要么把那几个变量 `export` 到环境里，否则会因为读不到 key 而静默退回假模型。
不确定用的是哪个模型时，看启动日志那行 `使用模型:`。

## 不放心就让它在副本里跑

```bash
npm run chat -- --sandbox
```

它会在一份 git worktree 工作副本里干活，你的文件一个都不会动。会话中途随时 `/diff` 看它改了什么，
满意了 `/apply` 打回来（只是一份未提交的改动，不满意 `git checkout -- .` 就没了），`/drop` 整个丢弃。

要求工作区是一个**至少有过一次提交**的 git 仓库，否则会直接报错退出。

## 常见问题

**跑起来报语法错误 / 不认识 `.ts`** —— Node 版本不够。`node -v` 确认 ≥ 22.18。

**明明配了 `.env`，却还在用假模型** —— 看启动日志：如果打了 `缺少模型配置（baseUrl/model/apiKey），回退到 FakeLlm`，
说明那三个变量没配齐；如果连这句都没有，多半是当前目录不对（见上一节那个坑）。想强制走真实模型用 `GB_LLM=real`。

**它一直在重复调同一个工具** —— 正常情况下不会。真撞上了会看到"已达工具步数上限"的兜底回复，
把任务拆小一点再问，或者 `GB_MAX_STEPS=40` 调大上限。

**想确认代码是好的** —— `npm test`（零依赖，用 Node 自带的 test runner）和 `npm run typecheck`（要先 `npm install`）。
